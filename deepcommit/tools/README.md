# AgentBench Tools

This directory contains tools for repository analysis, milestone construction, validation, and support utilities for the AgentBench project.

## Tool Categories

### Analysis Tools (分析类) ✅ Implemented

Repository entity retrieval and search tools:

- **`get_issue_context`** - Retrieve issue metadata with optional expansions (conversation, events, closing PRs)
- **`get_pr_context`** - Retrieve PR metadata with optional expansions (commits, files, timeline, comments, checks, linked issues)
- **`get_commit_context`** - Retrieve commit metadata with optional expansions (files, stats, PR refs, diff, issue refs)
- **`get_release_context`** - Retrieve release metadata with change lists (commits, files, PRs, issues)
- **`get_commits_diff`** - Compute diff between two refs with optional summary, files, patches, commits
- **`search_entities`** - Unified search for commits, PRs, releases, and issues

## Usage

### Basic Usage

```python
from agentbench.tools import (
    get_issue_context,
    get_pr_context,
    get_commit_context,
    get_release_context,
    get_commits_diff,
    search_entities
)

# Get issue information
issue = get_issue_context(
    repo_id="/path/to/repo",
    issue_number=123,
    expand=["conversation", "events"]
)

# Get PR information
pr = get_pr_context(
    repo_id="/path/to/repo",
    pr_number=456,
    expand=["files", "commits"]
)

# Get commit details
commit = get_commit_context(
    repo_id="/path/to/repo",
    sha="abc123def456",
    expand=["files", "stats", "diff"]
)

# Get release information
release = get_release_context(
    repo_id="/path/to/repo",
    tag="v2.1.0",
    expand=["commits", "files", "prs"]
)

# Compare two refs
diff = get_commits_diff(
    repo_id="/path/to/repo",
    base_ref="v2.0.0",
    head_ref="v2.1.0",
    expand=["summary", "files", "commits"]
)

# Search for entities
results = search_entities(
    repo_id="/path/to/repo",
    query="bug fix",
    types=["commit", "pr", "issue"],
    filters={
        "time_range": {
            "from": "2023-01-01T00:00:00Z",
            "to": "2023-12-31T23:59:59Z"
        }
    }
)
```

### MCP Server Defaults

The MCP server endpoints consume the same analysis helpers but now resolve `repo_id` from the `DEEPCOMMIT_COLLECT_DIR` environment variable by default. Set this variable to the target repository identifier or local path (for example, `export DEEPCOMMIT_COLLECT_DIR=/path/to/repo.git`) before launching the server. You can still override the repository for a specific call by passing the optional `repo_id` argument when invoking the MCP tool directly.

#### Configuring `DEEPCOMMIT_COLLECT_DIR`

Source the repo’s `.envrc` (generated by `setup-dev.sh`) so all static paths remain in sync. Before each Agent run, export the run-specific collection root:

```bash
export DEEPCOMMIT_COLLECT_DIR="/absolute/path/to/run/DATA/raw_github_repo"
```

Leave `DEEPCOMMIT_REPO_ROOT` and `DEEPCOMMIT_PREPROCESSED_ROOT` untouched—they continue to come from `.envrc`.

### Repository Identifier Formats

The `repo_id` parameter accepts:

1. **Local path**: `/path/to/local/repo` - Points to a local git repository
2. **GitHub format**: `owner/repo` - Will be resolved to local clone (TODO: implement resolution)

## Data Requirements

### For Basic Operation

- Git repository with standard structure
- Python packages: `pygit2`, `pathlib`, `datetime`, `re`, `typing`

### For Enhanced Operation

- Data files in `collect/data/` directory:
  - `releases.jsonl` - Release information
  - `pull_requests.jsonl` - PR metadata
  - `issues.jsonl` - Issue data
  - `commits.jsonl` - Commit information (optional)

### For Index-based Search

- Built index using `IndexTool` from `collect/repo/index_tool.py`
- Index file: `.index_cache.pkl` in data directory

## Error Handling

All tools include comprehensive error handling:

- **Repository Errors**: Invalid paths, missing repositories
- **Git Errors**: Invalid SHAs, missing refs, corrupt objects
- **Data Errors**: Missing files, invalid formats, corrupted indices
- **Platform Errors**: API limits, authentication failures, network issues

Error information is included in the `diagnostics` field of all responses.

## Performance Considerations

### Pagination

All list-returning functions support pagination:
- `limit` parameter controls page size
- `cursor` parameter for pagination state
- `pagination` field in response with next cursor

### Memory Usage

- Large diffs are truncated (`patch_limit_lines`, `diff_limit_lines`)
- Text fields are truncated (`body_limit_chars`, `notes_limit_chars`)
- File lists are paginated to prevent memory issues
